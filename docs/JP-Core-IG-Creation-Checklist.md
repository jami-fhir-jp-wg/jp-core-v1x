## 4. プロファイル設計

### 4.1 設計原則の確認

- [ ] **既存定義の再利用を優先する方針を確認した**
  - JP Core、FHIR 国際版、他 IG で定義済みのものを優先利用
- [ ] **将来の拡張性を確保する方針を確認した**
  - 派生 IG でさらに拡張できるよう過度な制約を避ける
- [ ] **各プロファイルが本当に必要か検討した**
  - 既存プロファイルで代用できないか？
- [ ] **MS 要素の実装要件を文書化した**
  - 送信者：データがあれば必ず送信
  - 受信者：受信・保存・表示が可能


### 4.3 プロファイル定義
- [ ] **JP Core プロファイルから派生させた**
  - 直接 Patient から派生せず、JP_Patient から派生
- [ ] **制約を追加する場合、その理由を文書化した**
- [ ] **Cardinality（多重度）変更の理由を記録した**
- [ ] **Must Support（MS）要素を明確にした**
- [ ] **新規 Extension が本当に必要か検討した**
  - JP Core、国際版に同等のものがないか確認
- [ ] **Slicing 定義が正しいか確認した**
- [ ] **派生 IG での拡張を妨げない設計にした**
  - extension ^slicing.rules = #open
  - 不要な 0..0 制約を避ける

## 5. 用語・コード体系

### 5.1 標準用語の活用

- [ ] **JP Core 標準の用語を最大限活用した**
- [ ] **MEDIS 標準マスターとの整合性を確認した**
- [ ] **JLAC コード等の日本固有コードに対応した**（必要な場合）

### 5.2 ValueSet と CodeSystem の設計

- [ ] **既存 ValueSet で対応できないか確認した**
- [ ] **新規 ValueSet を作成する場合、既存 ValueSet との重複がないか確認した**
- [ ] **複数プロファイルで同じ ValueSet を共有した**
  - 同じ概念は同じ ValueSet を使用
- [ ] **外部用語集（LOINC、SNOMED CT 等）のライセンスを確認した**
- [ ] **copyright 要素にライセンス情報を記載した**

### 5.3 CodeSystem の定義

- [ ] **既存 CodeSystem（LOINC 等）で表現できないもののみ新規作成した**
- [ ] **CodeSystem の URL、status、content 等を適切に設定した**
- [ ] **各コードに display と definition を記載した**

## ✅ 重要な設計原則（再確認）

作成完了前に、以下の原則を守れているか最終確認してください。

### DRY 原則（Don't Repeat Yourself）

- [ ] 同じ定義を複数箇所で作成していない
- [ ] 共通要素は基底プロファイルとして定義している
- [ ] ValueSet/CodeSystem を再利用している

### 既存資産の活用

- [ ] JP Core、FHIR 国際版、他の IG で定義済みのものを最大限活用している
- [ ] 新規作成前に必ず既存定義を確認している
- [ ] 車輪の再発明を避けている

### 拡張性の確保

- [ ] 派生 IG での拡張を想定した設計にしている
- [ ] 過度な制約（0..0 等）を最小限にしている
- [ ] Extension slicing を open にしている

### IHE 準拠

- [ ] アクタベースの設計にしている
- [ ] トランザクション定義を明確にしている
- [ ] ユースケース駆動で仕様を策定している

### ライセンスとコンプライアンス

- [ ] すべてのコンポーネントのライセンスを明示している
- [ ] 依存関係を明確に文書化している
- [ ] 第三者権利を尊重し適切に表記している
